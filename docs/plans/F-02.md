# F-02 Docker Compose development environment

## Summary

Add a Docker Compose dev stack so `docker compose up` brings up the API plus its backing services, all with health checks and dependency ordering. Add a real `GET /readyz` to the API (200 when MySQL and Redis are reachable, 503 when not). Add the `test` compose profile (isolated MySQL and Redis for later integration tests), the `.env.example` compose variables, and the README quick start.

Two services in the SRD scope line do not have code yet: `worker` (F-04) and `web` (F-06). They are deferred to those features (ADR 0006, ambiguity 1). Everything else in the scope line is built: api, mysql, redis, minio (+ bucket creation), mailpit, leetcode-api (pinned).

Refs: DOCKER-001..009, DOCKER-012, SEC-023, SEC-005, SEC-007, SEC-019, TD-011, TD-016, REL-007, SRD 22, 22.1, 27. Not in scope per Refs: DOCKER-010 (production image) and DOCKER-011 (migration step).

### Compose design

| Service                     | Image / build                                                                                                      | Host ports (all bound to `127.0.0.1`) | Health check                                                                                                                                   | Depends on                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| mysql                       | `mysql:8.4`, utf8mb4 (`--character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci`), volume `mysql-data` | 3306                                  | `mysqladmin ping -h 127.0.0.1` with the root password                                                                                          | none                                                          |
| redis                       | `redis:7-alpine`                                                                                                   | 6379                                  | `redis-cli ping`                                                                                                                               | none                                                          |
| minio                       | pinned `minio/minio:RELEASE.<tag>`, volume `minio-data`                                                            | 9000 (S3), 9001 (console)             | `mc ready local` (verify at build; fall back to `/minio/health/live`)                                                                          | none                                                          |
| minio-init                  | pinned `minio/mc:RELEASE.<tag>`, one-shot, `restart: "no"`: `mc mb --ignore-existing local/$S3_BUCKET`             | none                                  | n/a (exits 0)                                                                                                                                  | minio healthy                                                 |
| mailpit                     | pinned `axllent/mailpit:<tag>`                                                                                     | 8025 (UI), 1025 (SMTP)                | `wget -qO- http://localhost:8025/livez` (verify path at build)                                                                                 | none                                                          |
| leetcode-api                | `alfaarghya/alfa-leetcode-api:2.0.4`                                                                               | NONE (`expose: 3000` only, SEC-023)   | `node -e fetch(...)` against `http://localhost:3000/`, any HTTP response below 500 counts as up (endpoint to be confirmed in F-15, DOCKER-008) | none                                                          |
| api                         | build `Dockerfile` target `dev`, bind-mount repo, `node_modules` in an anonymous volume, command `npm run dev`     | 3000                                  | `wget -qO- http://localhost:3000/readyz`                                                                                                       | mysql, redis `service_healthy` (not leetcode-api, DOCKER-009) |
| mysql-test (profile `test`) | `mysql:8.4`, tmpfs, `MYSQL_ALLOW_EMPTY_PASSWORD=yes`, db `edumetrics_test`                                         | 3307                                  | `mysqladmin ping`                                                                                                                              | none                                                          |
| redis-test (profile `test`) | `redis:7-alpine`, no persistence                                                                                   | 6380                                  | `redis-cli ping`                                                                                                                               | none                                                          |

Notes:

- api container env (overrides `.env` values of the same name; dotenv never overrides existing env): `DATABASE_URL=mysql://${MYSQL_USER}:${MYSQL_PASSWORD}@mysql:3306/${MYSQL_DATABASE}`, `REDIS_URL=redis://redis:6379`, `APP_BASE_URL`, `CORS_ORIGINS`, `NODE_ENV=development`, plus provider selectors. Everything else comes from `env_file: .env`.
- Secrets have no defaults in the compose file: `${MYSQL_PASSWORD:?copy .env.example to .env}`. The test-profile services use passwordless throwaway containers, so the file holds no credentials at all.
- `.env.example` compose-only block: `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `S3_BUCKET`. They are read by Compose, not by the API Zod schema (the API does not use S3 until F-11, so no API config is added now). Comment: use URL-safe characters in `MYSQL_PASSWORD`.
- Service names are the DNS names (DOCKER-001), so `http://leetcode-api:3000` resolves from the api container.

## Security considerations

| Threat                                                         | Handling                                                                                                                                                                                                                                     |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| leetcode-api exposed publicly (SEC-023)                        | `expose` only, no `ports:`; image pinned to `2.0.4`; smoke test asserts both.                                                                                                                                                                |
| Backing services reachable from the network (SEC-005, SEC-007) | All published ports bind to `127.0.0.1`, so DB, Redis, MinIO and Mailpit are not reachable from the LAN.                                                                                                                                     |
| Secrets in code or images (DOCKER-003, SEC-005)                | Compose has no credential defaults; values come from the gitignored `.env`. Dockerfile has no secrets. `.dockerignore` keeps `.env` out of the build context. Test-profile containers are passwordless, throwaway (tmpfs) and loopback-only. |
| Information disclosure from `/readyz`                          | Fixed message, no dependency names, hosts, ports or error text in the body. Details go to the server log only (SEC-014 redaction already applies; URLs with credentials are never logged, only the check name).                              |
| SSRF via probe (SEC-019)                                       | Probe targets come only from validated `DATABASE_URL` and `REDIS_URL` at startup; no request input reaches the probe.                                                                                                                        |
| Unauthenticated endpoint used to cause work or hang the API    | 1 s timeout per probe, both run in parallel, sockets always destroyed on success, error and timeout. Rate limiting (SEC-016 general limit) does not exist yet; deferred to its feature and noted.                                            |
| Container runs as root                                         | Dev image runs as `USER node`. Full hardening (multi-stage, no dev deps) is DOCKER-010 in F-23.                                                                                                                                              |
| Pinned images (supply chain)                                   | All images pinned to a version tag; bumping is deliberate. Digests are not used (simplicity).                                                                                                                                                |
| Dependency risk (SEC-021)                                      | No new npm dependencies.                                                                                                                                                                                                                     |
| Scanner suppression                                            | No `eslint-disable`, `nosemgrep` or ignores (CLAUDE.md).                                                                                                                                                                                     |

## SRD ambiguities and proposed resolutions

1. **Scope lists `web` and `worker` but `apps/web` (F-06) and `src/worker.ts` (F-04) do not exist.** Options: placeholders, or defer. Resolution: defer the two services and add them in F-04 and F-06, where the real code lands (CLAUDE.md: no unneeded artifacts). The acceptance criteria are still met for every service that exists. ADR 0006. Please confirm this, since it is a deviation from the Scope line.
2. **"Reachable" for `/readyz` with no Prisma or Redis client yet.** Adding `mysql2`/`ioredis` now conflicts with "no dependencies the feature doesn't need" and F-03/F-04 will bring real clients. Resolution: TCP connect probe, zero dependencies; a fresh connection per request also satisfies the reconnect criterion. Weakness: proves the port accepts connections, not that auth or queries work. F-03/F-04 should upgrade the checks to `SELECT 1` and `PING` behind the same `ReadinessCheck` interface. ADR 0005.
3. **503 body shape.** CONV-004 has no fitting code. Resolution: add `SERVICE_UNAVAILABLE` (503) to the catalog in `packages/shared`, noted in ADR 0005, instead of overloading `INTERNAL_ERROR` or a provider code.
4. **leetcode-api health endpoint is "confirmed during F-15" (DOCKER-008).** Resolution: F-02 uses `GET /` and treats any HTTP response below 500 as healthy (proves the server is listening). F-15 may tighten it. Verify the container has `node` (it is a Node app) before relying on it.
5. **`docker compose up` "from a clean clone" vs required `.env`.** Resolution: README quick start includes `cp .env.example .env` (same as F-01); compose fails fast with a clear message if the secrets are missing, instead of shipping default passwords.
6. **MinIO and Mailpit variables.** Resolution: compose-only variables in `.env.example`; API config schema (S3__, SMTP__) is added by F-11 and F-08.
7. **`mysql migrate dev` needs a shadow database, and the app user cannot create databases.** F-03's concern; noted for that plan (probably a MySQL grant via an init script then), not solved here.
8. **Image versions.** SRD pins only leetcode-api. Resolution: pin every image by version tag; MySQL 8.4 matches CI.

# F-01 Repository scaffold and core conventions (backend only)

## Summary

Turn the empty kit repo into an npm-workspaces monorepo with the backend foundation every later feature builds on. It has TypeScript strict, ESLint (with `eslint-plugin-security`), Prettier and Vitest. The `packages/shared` skeleton holds error codes, the envelope schemas and the pagination schemas. `apps/api` gets a Zod env config that fails fast (including TD-016 mock rejection in production), a pino logger with central redaction, and request-ID middleware. It also gets the error classes and central error handler, response helpers, validation middleware, a cursor pagination helper, a 100 KB body limit, helmet, CORS allow-list, `GET /healthz`, and OpenAPI generation setup.

No database, Redis, queue, auth or frontend is added. It creates the npm scripts `scripts/verify.sh` requires (`lint`, `typecheck`, `test`, `test:coverage`, `test:integration`, `format:check`, `build`). `prisma:validate`, `db:check-migrations` and `db:migrate:deploy` come in F-03.

Refs: TD-001..005, 007, 008, 016; CONV-001..004, 006..009; API-003..006; SEC-012, 014, 017; SRD 7.2, 7.3, 21 (logging), 22.1, 27.

## Endpoints

| Method and path                       | Auth | Request | Success                                                            | Errors                                                             |
| ------------------------------------- | ---- | ------- | ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `GET /healthz` (outside `/api/v1`)    | none | none    | `200 {"success":true,"data":{"status":"ok"}}`, with `X-Request-Id` | none expected                                                      |
| `GET /api/docs` (non-production only) | none | none    | `200` OpenAPI 3 JSON document                                      | `404 RESOURCE_NOT_FOUND` when `NODE_ENV=production`                |

The error handler is exercised by test-only routes mounted via `mountRoutes`. They cover a validation failure (400 with `details`), a thrown `AppError`, a thrown unexpected `Error` (500 `INTERNAL_ERROR`, no stack in the body), a malformed JSON body (400), and an oversized body (413 `PAYLOAD_TOO_LARGE`).

Envelope shapes follow CONV-002/003 exactly. `details` appears only for `VALIDATION_ERROR`, as `[{path, message}]` with `path` dot-joined. `X-Request-Id` is on every response, including errors and CORS preflight (CONV-009).

## Test plan

Acceptance criteria to tests:

| Acceptance criterion                                                                    | Test(s)                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run lint`, `typecheck`, `test` pass                                                | The CI and `verify.sh F-01` run is the proof. Also `format:check`, `test:coverage`, `test:integration` and `build` pass.                                                                                                                                                                                                                           |
| Missing required env var exits with a clear error                                       | Unit: `loadConfig({})` throws `ConfigError` listing each missing variable name; message contains no values. Integration: spawn `tsx src/server.ts` with an env missing `DATABASE_URL`, assert exit code ≠ 0 and stderr names the variable.                                                                                                         |
| `NODE_ENV=production` and `NEWS_PROVIDER=mock` exits with a clear error                 | Unit: `loadConfig` rejects mock for `NEWS_PROVIDER` and `AI_PROVIDER` when production, and accepts them in development and test. Integration: spawn with production and mock, assert non-zero exit and a message naming `NEWS_PROVIDER`.                                                                                                           |
| Unknown route returns 404 in the envelope with requestId                                | Integration (Supertest): `GET /nope` gives 404, `error.code=RESOURCE_NOT_FOUND`, `error.requestId` equals the `X-Request-Id` header. Also checks POST and a path under `/api/v1/unknown`.                                                                                                                                                          |
| Unexpected error gives 500 `INTERNAL_ERROR` without a stack trace; the stack is in logs | Integration: test route throws `new Error("boom secret-detail")`. Assert body has code `INTERNAL_ERROR`, a generic message, no `stack` key, and the body does not contain "boom" or "secret-detail". Assert the captured log stream contains the stack, `requestId` and `err`.                                                                     |
| Logger redacts authorization headers, cookies, password fields                          | Unit: log `{req:{headers:{authorization,cookie}}, password, newPassword, token, refreshToken}` into an in-memory stream and assert `[REDACTED]`, with no raw secret substring anywhere in the output. Integration: send a request with `Authorization`, `Cookie` and a JSON body containing `password` through pino-http and assert nothing leaks. |

Additional tests needed for the scope items:

- Env: defaults (`PORT`, `LOG_LEVEL`), coercion, bad URL, `CORS_ORIGINS` parsing (trim, dedupe, reject `*`, reject non-origin values), bad `LOG_LEVEL`.
- Request ID (CONV-009): generated when absent; propagated when valid; replaced when invalid (too long, CR/LF, illegal characters).
- Error handler: `ZodError` to 400 with `details`; `AppError` subclasses map to the CONV-004 status for every code; non-`Error` throw; `headersSent` case; Retry-After set for `RATE_LIMITED`.
- Validation middleware: body, query and params; unknown body field rejected (strict, CONV-007); max-length string; valid input coerced and exposed via `req.validated`.
- Body limit (API-006, CONV-008): a body just under 100 KB is accepted; over 100 KB gives 413 `PAYLOAD_TOO_LARGE`; malformed JSON gives 400 with no parser internals in the message.
- Pagination: default 20, max 100, `limit=0`, `limit=101` and non-numeric rejected; cursor round-trip; tampered or non-base64 or wrong-shape cursor gives `VALIDATION_ERROR`; `buildPage` with `limit+1` rows sets `nextCursor`, and exact-fit and empty sets give `nextCursor: null`.
- Response helpers: success envelope, paginated `meta.pagination`.
- CORS (SEC-012): an allowed origin gets `Access-Control-Allow-Origin` (echoing that origin) and `Allow-Credentials: true`; a disallowed origin gets no ACAO header; preflight works; no `*` ever.
- helmet (SEC-017): `X-Content-Type-Options: nosniff`, CSP includes `frame-ancestors 'none'`, no `X-Powered-By`, HSTS only in production.
- `/healthz` and `/api/docs`: docs reachable in development and test, 404 in production; spec lists `/healthz`.
- Shared package: error-code catalog matches CONV-004 (code to status), envelope schemas accept and reject the right shapes.

Ownership (IDOR), auth and provider-failure tests: not applicable in F-01. There are no student-owned records, auth or outbound calls yet. The 404 envelope that later IDOR tests rely on (CONV-005) is what the unknown-route and `NotFoundError` tests prove. Tests never call live Codeforces or LeetCode.

Coverage: `test:coverage` enforces ≥80% lines on `apps/api/src` (excluding `server.ts`, config-exit glue and type files), so the gate fails below threshold (TEST-009). Unit tests are `*.test.ts`; integration tests are `*.int.test.ts` and run via `test:integration`. F-01 integration tests use Supertest on the app factory and need no MySQL or Redis.

## Security considerations

| Threat                                                    | Handling                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Information disclosure through errors (API-004, CONV-004) | The central handler returns only `code`, a safe message and `requestId`. Unknown errors are always `INTERNAL_ERROR` with a fixed message. Stack and cause are logged server-side only. Body-parser and Zod internals are mapped to fixed messages; Zod details expose only `path` and `message`.                                                                                 |
| Secrets in logs (SEC-014, SRD 21)                         | Centralized `REDACT_PATHS`: `req.headers.authorization`, `req.headers.cookie`, `res.headers["set-cookie"]`, and `password`, `newPassword`, `currentPassword`, `token`, `accessToken`, `refreshToken`, `clientSecret` at top level and nested. The HTTP logger logs method, route template (or `unmatched`), status, duration and requestId only. No query string, body or email. |
| Secrets in startup errors                                 | `ConfigError` reports variable names and reasons only, never values.                                                                                                                                                                                                                                                                                                             |
| Log injection or header injection via `X-Request-Id`      | Accepted only if it matches `^[A-Za-z0-9_-]{8,64}$`; otherwise a fresh UUID is generated.                                                                                                                                                                                                                                                                                        |
| CORS misconfiguration (SEC-012)                           | Allow-list from `CORS_ORIGINS`, validated at startup (no `*`, must be `http(s)` origins). Origin function callback, never `origin: true` or `'*'` (also enforced by the project Semgrep rule). `credentials: true` applies only to allow-listed origins.                                                                                                                         |
| Missing security headers (SEC-017, SEC-013)               | helmet defaults plus API CSP `default-src 'none'; frame-ancestors 'none'`, `X-Powered-By` off, HSTS in production only.                                                                                                                                                                                                                                                          |
| Oversized or hostile bodies (API-006, CONV-008)           | `express.json({limit:'100kb', strict:true})`. URL-encoded parsing is not enabled. Strict Zod schemas reject unknown fields (CONV-007).                                                                                                                                                                                                                                           |
| Mock or none providers reaching production (TD-016)       | Startup validation rejects `mock` in production. Covered by unit and process-level tests.                                                                                                                                                                                                                                                                                        |
| Doc exposure                                              | `/api/docs` is not mounted when `NODE_ENV=production`.                                                                                                                                                                                                                                                                                                                           |
| Dependency risk (SEC-021)                                 | Lockfile committed; `npm audit` runs via the security gate.                                                                                                                                                                                                                                                                                                                      |
| Scanner suppression                                       | No `eslint-disable`, `nosemgrep` or ignores are added (CLAUDE.md). Anything `eslint-plugin-security` flags gets fixed in code.                                                                                                                                                                                                                                                   |

Deferred to the features that own them: rate limiting (SEC-016), auth and JWT (Section 6), IDOR tests (SEC-022), SSRF controls (SEC-019, no outbound HTTP in F-01).

## SRD ambiguities and proposed resolutions

1. **Which env vars are required in F-01?** SRD 22.1 lists the full set, but most belong to later features and "no dependencies or config the feature doesn't need" applies. Resolution: F-01 defines the foundation vars (`NODE_ENV`, `PORT`, `LOG_LEVEL`, `APP_BASE_URL`, `CORS_ORIGINS`, `DATABASE_URL`, `REDIS_URL`) and the provider selectors (`NEWS_PROVIDER`, `AI_PROVIDER`, `VIDEO_SEARCH_PROVIDER`, default `none`). Required with no default: `APP_BASE_URL`, `CORS_ORIGINS`, `DATABASE_URL`, `REDIS_URL` (only URL-validated; CI already supplies the last two). Later features add their own vars to the schema and `.env.example`. ADR 0001.
2. **Layout vs "backend only".** TD-002 lists `apps/web` and `content/`. Resolution: create only `apps/api` and `packages/shared` now; `apps/web` arrives in F-06 and `content/` in F-12. Workspace globs already cover them.
3. **Coverage threshold "≥80% lines for services"** with no services yet. Resolution: apply 80% lines to all of `apps/api/src` minus entrypoints now; narrow or extend the include list as modules appear.
4. **`/healthz` location and depth.** SRD gives no path or semantics. Resolution: root-level `/healthz`, liveness only (no DB or Redis checks, which do not exist yet), standard envelope; readiness checks can be added in F-02/F-23. Not versioned, so it stays stable for container health checks.
5. **`/api/docs` format.** TD-005 says "served"; Swagger UI would add a dependency. Resolution: serve the OpenAPI JSON only, non-production; a UI viewer is a later option. Only `/healthz` is documented now, and each later feature registers its own routes.
6. **Express version.** SRD says Express.js only. Resolution: Express 5 (native async error propagation). Parsed input goes on `req.validated`, not `req.query`, because `req.query` is read-only in Express 5.
7. **Error for unknown routes and bad JSON.** CONV-004 has no dedicated codes. Resolution: unknown route gives `RESOURCE_NOT_FOUND` 404; malformed JSON gives `VALIDATION_ERROR` 400 without `details`; oversized body gives `PAYLOAD_TOO_LARGE` 413.
8. **Request ID format.** CONV-009 says "valid" without defining it. Resolution: `^[A-Za-z0-9_-]{8,64}$`, otherwise generated (see security table).
9. **Node version.** TD-001 says 20 LTS or newer; the dev machine runs 24 and CI runs 20. Resolution: `engines >=20`, `.nvmrc` 20, code avoids features newer than 20.
10. **`test:integration` with no MySQL or Redis yet.** The script is required now. Resolution: it runs `*.int.test.ts` (Supertest on the app factory plus process-level config tests); DB and Redis containers are used once F-03/F-04 need them.
11. **Mock rejection scope (TD-016).** Applies to `NEWS_PROVIDER` and `AI_PROVIDER` (the only providers with a `mock` value). `EMAIL_PROVIDER=console` in production is left to F-08.

Items 1, 4 and 5 get ADRs in `docs/decisions/`; the rest are noted in the feature summary.
